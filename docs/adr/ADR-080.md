# ADR-080: The published image signed with GitHub's own keyless signing, and what it was built from published with it

**Status:** proposed, 9 October 2026, with the backlog claim (0191, part 4); to be accepted in the pull request that
builds it, which says where the build differs from this plan. The owner's decision, the same day: yes to part 4, "with
GitHub's own keyless signing, which costs nothing", and again "as recommended" to the plan for part 6 that puts part 4
first. Written by session securevibe-e9.

**Governs:** `.github/workflows/rust.yml`, whose publish job signs what it pushes once this is built (ADR-051 governs the
same file, for its checks). A pull request that changes how the image is signed, or what is published
with it, changes this record too, or says in its description why it does not (`docs/adr/README.md`).

## Context

`ghcr.io/abbyshade111/stackvet-sv` is built and pushed by CI on every change to `main` that passes its tests. Nothing
lets somebody who pulls it check that it came from that CI run, from this repository, at the commit its tag names,
rather than from whoever got hold of a token that can push packages. The GitHub Action in part 6 would pull the image
into other people's builds every time it runs, so the question gets sharper there.

No binary of `sv` is published: there are no release files, and installing without Docker builds from source. So
there is nothing besides the image to sign yet.

## Decision

- **GitHub's build provenance** (`actions/attest-build-provenance`, GitHub's own action, pinned to a commit like the
  others): after the image is pushed, the `publish` job writes a signed statement of what built it (this repository,
  this workflow, this commit) for the image's digest, and pushes it to the registry beside the image.
- **Keyless:** the signature comes from a certificate tied to this workflow run through GitHub's OIDC token, issued
  through Sigstore. No key is kept, so none can leak. Free for a public repository.
- **Checked by the owner of an app** with `gh attestation verify oci://ghcr.io/abbyshade111/stackvet-sv:latest
  --owner abbyshade111`, which the README says how to run.
- **The job gains `id-token: write` and `attestations: write`**, for that job only; every other job keeps read-only
  permissions.
- **A binary, when one is published**, gets the same provenance, in the pull request that publishes it.

## Alternatives considered

- **`cosign sign` with a key kept as a secret.** A key is one more thing to keep and rotate, and leaking it lets
  anybody sign.
- **`cosign sign` keyless, as well as or instead of the provenance.** The same Sigstore signing underneath, with a
  third-party tool to install and pin; GitHub's own action keeps the job to GitHub's actions, as it is now.
- **Not signing until a binary is published.** The image is what people pull now, and what the Action would pull.

## Consequences

- The `publish` job's permissions widen by two, and the record of each signing is public in Sigstore's log, naming
  this repository and workflow, which are public already.
- Images published before this change carry no provenance; `latest` gains it at the first push to `main` after.
