# ADR-042: The test model answers in the shape the app asked for, and a wrong shape refused is credit for C7.1.1

**Status:** proposed, 6 October 2026, with the backlog claim (BACKLOG, "The AI service failing", item 10's leftover
C7.1.1). To be made accepted, or changed, in the pull request that builds it.

**Governs:** `crates/sv-run/assets/model-provider.mjs`, where the test model decides the shape of each answer. A pull
request that changes it changes this record too, or says in its description why it does not (`docs/adr/README.md`).

## Context

An app can ask its AI service for an answer in a set shape: a JSON schema (OpenAI's `response_format` or the
Responses API's `text.format`, Anthropic's structured outputs), plain JSON mode, or a tool the model is made to call,
which is how libraries such as Instructor get structured answers. The test model `sv run` puts in place of the
service has always answered in plain text. An app that asked for a shape cannot read that, so every AI question asked
of it fails for a reason of the test model's making, and a failure the check reads as the app's own (the plain
message after the service failed, for one) is a false finding.

C7.1.1 (AISVS, level 1) asks that the app checks every answer from the model against the shape it defined and
refuses one that does not match. No check spoke to it.

## Decision

- **The test model answers in the shape asked for.** When a request names a JSON schema, its answer is JSON that
  fits it, with the reply's text in its text fields; in JSON mode, a JSON object holding the reply; when a tool is
  forced, a call to that tool with arguments that fit its schema. Nothing else about what each kind of message does
  changes.
- **A new kind of message answers in the wrong shape**, carrying a marker: JSON whose fields have the wrong types
  when there is a schema to break, and text that is not JSON when there is none.
- **What counts:** the marker in the app's answer is a finding against C7.1.1, the app having used what did not fit.
  Credit only when the same app was seen to show an ordinary answer of the right shape, and then answered the
  wrong-shaped one without the marker and without failing (no 5xx). An app that asked for no shape is not assessed.
  A crash is not credit: it rejects the answer, but not by checking it.

## Alternatives considered

- **Leaving the test model in plain text,** and reporting structured apps' AI questions as not assessed. Honest, but
  it gives no answers at all for apps built the way the libraries recommend, and does nothing about the false
  finding.
- **Credit for any answer without the marker.** An app that stores the answer and shows something else would be
  credited for a check it never made, so credit needs an app seen to show what the model said.
