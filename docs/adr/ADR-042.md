# ADR-042: The test model answers in the shape the app asked for, and a wrong shape refused is credit for C7.1.1

**Status:** accepted, 6 October 2026. Proposed the same day with the backlog claim (#851; BACKLOG, "The AI service
failing", item 10's leftover C7.1.1), and built as proposed (DESIGN, "Answers in the shape the app asked for, and
C7.1.1").

**Governs:** `crates/sv-run/assets/model-provider.mjs`, where the test model decides the shape of each answer. A pull
request that changes it changes this record too, or says in its description why it does not (`docs/adr/README.md`).

## Context

An app can ask its AI service for an answer in a set shape: a JSON schema (OpenAI's `response_format` or the
Responses API's `text.format`, Anthropic's structured outputs), plain JSON mode, or a tool the model is made to call,
which is how libraries such as Instructor get structured answers. The test model `sv run` puts in place of the
service has always answered in plain text. An app that asked for a shape cannot read that, so every AI question asked
of it fails for a reason of the test model's making, and a failure the check reads as the app's own (the plain
message after the service failed, for one) is a false finding.

C7.1.1 (AISVS, level 1) asks that the app checks every answer from the model against the shape it defined and
refuses one that does not match. No check spoke to it.

## Decision

- **The test model answers in the shape asked for.** When a request names a JSON schema, its answer is JSON that
  fits it, with the reply's text in its text fields; in JSON mode, a JSON object holding the reply; when a tool is
  forced, a call to that tool with arguments that fit its schema. Nothing else about what each kind of message does
  changes.
- **A new kind of message answers in the wrong shape**, carrying a marker: JSON whose fields have the wrong types
  when there is a schema to break, and text that is not JSON when there is none.
- **What counts:** the marker in the app's answer is a finding against C7.1.1, the app having used what did not fit.
  Credit only when the same app was seen to show an ordinary answer of the right shape, and then answered the
  wrong-shaped one without the marker and without failing (no 5xx). An app that asked for no shape is not assessed.
  A crash is not credit: it rejects the answer, but not by checking it.

## Alternatives considered

- **Leaving the test model in plain text,** and reporting structured apps' AI questions as not assessed. Honest, but
  it gives no answers at all for apps built the way the libraries recommend, and does nothing about the false
  finding.
- **Credit for any answer without the marker.** An app that stores the answer and shows something else would be
  credited for a check it never made, so credit needs an app seen to show what the model said.

## Where the build differs from the proposal

- **Numbers:** zero where the schema allows it, else the nearest number it does. Using a schema's `minimum` as written
  gave a whole number of -(2^53 - 1), which is what zod writes for one, and read oddly though it fit.
- **One more case not assessed:** a limiter's answer (429, or 503 with `Retry-After`) to the wrong-shaped message, as
  ADR-021 reads one.
- **Checked with real libraries:** the OpenAI SDK's `parse` with zod, over chat completions and the Responses API,
  and the Anthropic SDK with a forced tool, each read the right shape and refused the wrong one, against the real
  test model under Node. Not run end to end with an app under `sv run`, which needs Docker.

## Later, 9 October 2026: the shape a Gemini request asks for

The test model answers Google's Gemini format too (the gap analysis of 7 October 2026, finding 13(g); the app is told
where it is by ADR-019, Later, the same day). Its shape is read as this record reads the others': JSON fitting a
schema when `generationConfig.responseMimeType` is `application/json` with `responseJsonSchema` or `responseSchema`;
a JSON object holding the reply in that mode without one; and a call to one function when
`toolConfig.functionCallingConfig.mode` is `ANY` and it names one function or only one is declared. Google's own
schema writes its types in capitals (`STRING`, `OBJECT`), so types are read in either case, which changes nothing for
the others. BADSHAPE breaks each as before, and `shape` in what was seen says which was asked for. The rule of this
record is unchanged: a wrong shape refused is credit for C7.1.1, and an app that asked for none leaves it not assessed.
Held by `crates/sv-run/tests/model_provider_gemini.rs`, run with Node.

## Later, 9 October 2026: whether a recalled note carried an injection

For RECALL, the test model now also reports `injection_seen`: whether a textbook injection's words ("ignore all
previous instructions") were anywhere in what the app handed it. The AI checks use it to ask whether a note the second
test user saved with an injection in it reaches the model as it was saved (`probe.ai-stored-injection-unscreened`,
C2.1.3, only ever a finding; the gap analysis's finding 13(e)). The shape of every answer is unchanged. This record's
rule is unchanged too: a wrong shape refused is credit for C7.1.1. Held by `crates/sv-run/tests/model_provider.rs`,
run with Node.

## Later, 9 October 2026: a reply that carries HTML

The test model has a new kind, MARKUP, whose reply carries raw HTML: an image tag whose failure to load runs a line of
script naming the message's tag. The AI checks use it to ask whether an app whose answer is a page of HTML writes the
reply into that page unencoded (`probe.ai-reply-html-unencoded`, V1.2.1, only ever a finding; the gap analysis's
finding 13(b)). An answer in JSON is not judged. Every other kind's answer is unchanged, and this record's rule is too.
Held by `crates/sv-run/tests/model_provider.rs`, run with Node.
