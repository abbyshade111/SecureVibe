# ADR-081: A GitHub Action that runs the published image on an app's pull requests

**Status:** accepted, 9 October 2026, in the pull request that builds it, after ADR-080's; proposed the same day with
the backlog claim (0191, part 6). The owner's decision, the same day: the plan session securevibe-e9 brought, "as
recommended", and then `@main` for the reference apps use (below). Written by session securevibe-e9.

**Governs:** `action.yml`, the Action itself, and its test (`crates/sv-cli/tests/action_file.rs`); and `Dockerfile`,
because the Action rests on what the image carries and refuses (no outside tool, and no starting the app). A pull request that changes
what these say about the Action changes this record too, or says in its description why it does not
(`docs/adr/README.md`).

## Context

`sv report` writes `findings.sarif`, which GitHub's code scanning reads, and the image runs `sv` with nothing else to
install. Wiring them into an app's pull requests takes a workflow somebody has to write by hand. An Action makes it
one line, `uses: abbyshade111/StackVet@v1`.

## Decision

The owner's answers to the six questions in the plan:

1. **After the image is signed** (ADR-080), so what the Action pulls can be checked.
2. **In this repository**, as `action.yml` at its root. Not listed on the Marketplace for now, which wants a
   repository holding only the Action; listing later changes nothing for its users. The plan said apps would write
   `abbyshade111/StackVet@v1`, but `v1` is the branch v1 is archived on, so that line would load the old app. Asked
   while it was built, **the owner chose `@main`**: always the newest, as the image is already published as `latest`
   from `main`, with no tag to keep or ever move. A repository that wants to choose when it changes can pin a commit.
   Version tags, or one moving tag, were the other choices; either can be added later without breaking `@main`.
3. **`sv` alone.** The image carries no outside tool, so the Action does not pass `--tools`; a repository that installs
   the tools itself can run `sv` the same way.
4. **Never `--run`.** It would start the code in the pull request, a stranger's on a pull request from a fork, on the
   runner, and the image refuses it already.
5. **Code scanning where it is available, the report everywhere:** `findings.sarif` uploaded to code scanning (free on
   a public repository, part of GitHub's paid security product on a private one), and always the report folder kept
   with the run and a short summary on the run's page, so a private repository without that product still gets the
   result.
6. **Report only, by default:** the Action fails the check only when a check could not run (exit 2). A `fail-on` input
   passes `--fail-on` on, for a repository that wants findings to block. An app with no `stackvet.toml` stops with a
   message saying how to add one, rather than guessing.

How it is built:

- **The published image is checked before it runs**: pulled, then `gh attestation verify` against this repository
  and its Rust workflow, so only an image the publish job signed (ADR-080) runs. An image given by name with the
  `image` input (one built from the Dockerfile, say) is run as given, and the run says so.
- **It runs with `--network none`**, as the README runs it, as the runner's own user rather than root, with the
  repository mounted read-only; it writes only its report folder, outside the repository.
- **Code scanning, `auto` by default**: uploaded for a public repository, and not for a pull request from a fork,
  whose token cannot write; `true` or `false` overrides it, `true` being for a private repository with GitHub's code
  security.
- **`security.md` is the summary** on the run's page, cut at 900,000 bytes since GitHub keeps 1 MiB a step; the whole
  report folder is kept with the run as an artifact.
- **The image job in CI runs the Action** on an example app with the image it just built, and on a folder with no
  `stackvet.toml`, where it must stop.

## Alternatives considered

The plan's: a repository of its own for the Marketplace; the outside tools added to the image; `--run`; failing on
findings by default. Each is answered above.
