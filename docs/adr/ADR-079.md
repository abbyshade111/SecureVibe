# ADR-079: An input flagged as an attack, and whether the flag stopped it (C11.4.2)

**Status:** proposed, 9 October 2026, with the backlog claim (0085, part 23); to be accepted in the pull request that
builds it. Asked for by the owner ("go ahead"). Written by session paper-facts.

**Governs:** `crates/sv-check/src/ai.rs`, where the check this record adds, probe.ai-flag-not-gating, joins what the
injection question saw with what the app's output recorded (ADR-071, ADR-073, ADR-074 and ADR-075 govern the same
file). A pull request that changes what it says about this changes this record too, or says in its description why it
does not (`docs/adr/README.md`).

## Context

AISVS C11.4.2 (level 2) reads: "Verify that inputs flagged as anomalous trigger gating actions." Nothing in StackVet
speaks to it. The AI checks send a textbook prompt injection and see whether it reached the test model, with a plain
message straight after as the control (C2.1.3); after the run they look in the app's output for a line recording that
injection as caught (C12.2.1). Each alone says one thing. Together they say whether the app, having flagged the input,
then stopped it: a detector that writes "blocked" and passes the message on anyway is the case this requirement is for.

## Decision

- **Judged only when both halves are known:** the app's output has a line recording the injection as caught, and the
  plain message after the injection reached the model, so a refusal of the injection was of the injection.
- **Credited, marked in part (ADR-053),** when the injection was recorded as caught and did not reach the model: the
  flag gated it. One kind of anomaly, a textbook injection, is tried.
- **A finding (medium)** when it was recorded as caught and still reached the model: detected, not gated.
- **Not assessed, and said,** when no line recorded it as caught (nothing was flagged that can be seen), or the plain
  message after it did not get through.

## Alternatives considered

- **Credit from the injection not reaching the model alone.** That is C2.1.3's credit already, and it does not show a
  flag: the app may refuse it without flagging anything.
- **C12.2.3 and C10.3.4 instead.** Left: C12.2.3 asks for rules against coordinated attempts, which one message cannot
  show (backlog 0140), and C10.3.4 needs a protocol handshake for each message, which an app that connects to its MCP
  server once at start-up never makes.
