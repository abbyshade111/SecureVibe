# ADR-065: Hidden characters sent into the AI feature, for C2.1.2 and C2.1.5

**Status:** accepted, 8 October 2026, in the pull request that builds it; proposed with the backlog claim (0085, part
13). Asked for by the owner ("please choose the next backlog item once it's merged"). Written by session paper-facts.

**Governs:** `crates/sv-run/assets/model-provider.mjs`, where the test model records which hidden characters arrived
(ADR-042 and ADR-064 govern the same file), and the two checks this record adds to the AI checks, probe.ai-hidden-input
and probe.ai-input-charset-unrestricted, in the AI checks' file in sv-check, which is not listed here, since it is
changed often for other reasons (as ADR-045 says of the same file). A pull request that changes what these say about
this changes this record too, or says in its description why it does not (`docs/adr/README.md`).

## Context

AISVS C2.1.2 (level 1) reads: "Verify that encoding and representation smuggling in inputs is detected and
mitigated. Approved mitigations include canonicalization, strict schema validation, policy-based rejection, or
explicit marking." C2.1.5 (level 1) reads: "Verify that the system implements a character set restriction for all
inputs. The restriction must use an allow-list approach that permits only characters that are explicitly required."
Nothing in StackVet speaks to either. The checks already look at hidden characters in the model's
replies (C7.3.4, `probe.ai-hidden-content-passed`), not in what the person sends in.

Invisible Unicode tag letters (U+E0020 to U+E007E) can spell an instruction a reader never sees and a model reads;
zero-width characters (U+200B, U+200D) split words past a screen; a right-to-left override (U+202E) shows text in
another order than it is read. Control characters (U+0001 to U+0008, U+001B) and private-use characters (U+E000) are
needed by no language.

## Decision

- **Two messages, after the plain one is answered.** One carries the tag letters spelling a short instruction, a
  zero-width space and joiner, and a right-to-left override, inside an ordinary request; the other carries the control
  and private-use characters. Apart, so an app that refuses control characters, or whose parser fails on them, does
  not hide what it does with the tag letters. No character is U+0000, and the tag letters follow no flag emoji, so no
  real subdivision flag is spelled.
- **The test model records, for each tag, which of the sent characters arrived** in the person's text it was given.
- **C2.1.2, probe.ai-hidden-input.** A finding (medium) when the tag letters or the override reach the model as they
  were sent. Credited, marked in part (ADR-053), when the visible request reached the model and none of them did, or
  when the app refused the message (an answer that is not a success, with nothing reaching the model) where the plain
  message before it was answered: one family of smuggling is tried, and encodings such as base64 or look-alike letters
  are not. Zero-width characters alone are said, not found: they are common in pasted text.
- **Explicit marking**, the fourth mitigation C2.1.2 names, cannot be told apart from passing the characters on, since
  a marking may take any form. An app that passes them on unchanged with a marking of its own is found; the finding
  says that marking is a mitigation the check cannot see, so its owner can record it as a false alarm.
- **C2.1.5, probe.ai-input-charset-unrestricted.** Only ever a finding (low): any of the control or private-use
  characters reaching the model unchanged shows no allow-list. None arriving does not show one exists, so it is
  never credited, and that is said.
- **Not asked** when the plain message did not reach the model or its reply did not come back, and said so; a
  limiter's answer is waited out once, as elsewhere.

## Alternatives considered

- **One message with everything.** Rejected: a parser that fails on a control character would answer it with an
  error, which would read as the tag letters refused.
- **Full credit for C2.1.2.** Rejected: one family of smuggling is part of the requirement.
- **Normalization, C2.1.1, from the same message.** Not here: an app may normalize with NFC on purpose, which leaves
  full-width letters alone, so a finding would be wrong too often (`docs/PARTIAL-CHECKS.md`: shown, not scored).

## Where the build differs from the proposal

- **A refusal needs a plain message after it.** A message refused counts only when a plain message straight after it
  reaches the model; otherwise an app that had stopped answering anything would be credited.
- **More cases said, none credited:** part of the hidden instruction arriving, and an answer of 200 that never reached
  the model (an app's own words in place of a refusal the check can read).
- **The credit says whether the zero-width characters were taken out too**, since they are left alone by many careful
  apps.
- **The coverage documents say "in part"** for C2.1.2 (`RUST_IN_PART`, ADR-018's Later entry of 8 October 2026), and
  C2.1.5 is listed as only ever a finding.
- **Not run end to end** with an app under `sv run`, which needs Docker; the test model's own test runs the recording
  under Node.
