# ADR-047: V3.4.3 is credited only for a Content-Security-Policy with the directives it names

**Status:** proposed, 7 October 2026, with the backlog claim. The decision is the owner's, of 7 October 2026 ("The
check should look for them"); to be made accepted in the pull request that builds it.

**Governs:** `crates/sv-check/src/probes.rs` (the list of missing headers both header checks read). A pull request that
changes what V3.4.3 is credited for changes this record too, or says in its description why it does not
(`docs/adr/README.md`).

## Context

V3.4.3 (ASVS 5.0, level 2) asks for a Content-Security-Policy that "as a minimum, a global policy must be used which
includes the directives object-src 'none' and base-uri 'none' and defines either an allowlist or uses nonces or
hashes". `probe.security-headers` (the pages a stranger sees) and `probe.private-page-headers` (the pages a signed-in
person sees) credited V3.4.3 for any Content-Security-Policy header at all, `frame-ancestors 'none'` alone included.
The prompt-library review of 7 October 2026 found it.

## Decision

- **A page's policy counts toward V3.4.3 only when it has all three:** `object-src 'none'` (or no `object-src` and
  `default-src 'none'`, which a browser reads the same way); `base-uri 'none'`, which nothing else stands in for; and
  a `default-src` or a `script-src`, the allowlist the requirement asks for.
- **A policy short of any is named in the header check's finding**, as a missing header is, with what it lacks. The
  four headers are judged together, as before, so V3.4.4, V3.4.5, and V3.4.6 are held back with it.

## Alternatives considered

- **A rule of its own for V3.4.3.** Clearer in the report, but the header checks credit their four requirements
  together, and splitting them is a larger change than the decision asked for.
- **Leaving the citation and saying "partly".** `sv` has no "partly"; a credit is a claim the requirement is met.
