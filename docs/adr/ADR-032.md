# ADR-032: Git, run in the app's folder, runs no program the app's repository names

**Status:** accepted. Found, reproduced, and built on 5 October 2026 by session securevibe-e9, at the owner's asking
to keep working off the backlog (BACKLOG, "`git ls-files` runs a program the app's repository names"), in branch
`claude/securevibe-e9-git-config`.

**Governs:** `crates/sv-check/src/git.rs`, `crates/sv-cli/tests/git_config.rs`. A pull request that changes any of
these changes this record too, or says in its description why it does not (`docs/adr/README.md`).

## Context

`sv check` runs one outside program in the app's own folder on the owner's computer, outside the container fence:
`git ls-files`, for the check that no secrets file was ever committed (`config.secrets-file-committed`). Git reads
the repository's own `.git/config`, which whoever wrote the app also wrote. Some settings there are programs git
runs. `core.fsmonitor` is one, and plain `git ls-files` ran it, reproduced on 5 October 2026 with git 2.x. An app
handed to the owner to check could run anything with the owner's rights while `sv` read it. The Docker image trusts
every repository (`safe.directory '*'`), so there too.

## Decision

- **Git is run through one place, `git::ls_files`,** which gives `core.fsmonitor=false` on git's command line. A
  setting given there wins over the repository's own.
- **Only what was shown to run is overridden.** Hooks were tried with a planted `core.hooksPath`
  (`post-index-change`, `reference-transaction`), and `ls-files` ran none, so nothing is given for them. A git
  command added to `git.rs` is tried against a planted repository the same way before it is used.

## Alternatives considered

- **Reading `.git/index` directly instead of running git.** No program at all, but a second reader of a format git
  changes (index versions 2 to 4, split and sparse indexes), and an unread index would read as "nothing committed".
  Set aside for now.
- **Running git without the repository's config.** Git has no switch for that; the system and global ones can be
  left out, the repository's cannot.
- **Overriding every setting that could name a program.** Most are never read by `ls-files`, and a guard that no
  test can catch is one nobody knows works.

## Consequences

- A planted `core.fsmonitor` no longer runs during `sv check`, and the committed-secrets check still asks git.
- If a later git starts running another program for `ls-files`, this does not stop it. The test that plants one is
  the place to add it.

## How it is held

`a_program_the_app_s_repository_names_is_not_run` (`crates/sv-check/src/git.rs`) and
`checking_an_app_runs_no_program_its_repository_names` (`crates/sv-cli/tests/git_config.rs`), each with a control that
shows plain git running the planted program, so the setup is the attack.
