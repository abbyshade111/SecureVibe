# ADR-016: The OWASP data files: one copy while both versions lived here, and two since

**Status:** accepted, in two parts. The first was decided with `sv`'s design and held until 26 September
2026. The second came with the move that day (BACKLOG, "Promote `sv` to the top of the repository"). Written
down here on 27 September 2026.

## Context

The standards SecureVibe checks against — OWASP ASVS 5.0, AISVS 1.0 and its Appendix C, and the Secure by
Design checklist — are large JSON files in `data/frameworks/`. `data/knowledge/` holds what is written about
them, such as which requirements apply under which conditions. None of it is code. A mistake in one of these
files is a wrong requirement in every report.

## Decision

**While `sv` was built beside v1 (until 26 September 2026), the files were shared, not copied.** `sv`, then in
`agnostic/`, read v1's `data/` in place, so one correction to ASVS fixed both products. The cost was that an
`sv` change to a shared file could break v1's tests. That happened at least once, with `applicability.json`.

**Since the move, there are two copies, and they are allowed to drift.** v1 took its copy with it to the `v1`
branch, and `v1-final` holds it too. `data/` in `main` is `sv`'s, and a correction made there does not
reach v1. v1 is archived, and a patch to it is made on its own branch, by choice (`CLAUDE.md`).

`data/` was kept whole in `main` rather than trimmed to what `sv` reads. When this was written, `sv` uses
three of the eleven files in `data/knowledge`: its crates load `applicability.json` and `threats.json` by
name, and `tools/pwned_passwords.py` samples `common-passwords.txt`. It loads all four files in
`data/frameworks`. The other eight are v1's: `examples.json`, `glossary.json`, `injection-patterns.json`,
`patterns.json`, `remediation.json`, `requirements-plain.json`, `sbd-rules.json`, and `wizard-copy.json`.
Editing one of those changes nothing `sv` does.

## Alternatives considered

- **Copy the files into `agnostic/` from the start.** Two copies of ASVS would drift from the first day, and
  nobody would know which one was right.
- **Trim `data/` at the move.** It is 1.6 MB, and the v1-only files do no harm in `main`. Removing them would
  have been one more change in a move that had to keep the paper's citations working.

## Consequences

- A correction to a standard in `main` is a correction for `sv` only. If v1 ever needs it, it is made again
  on the `v1` branch.
- Someone editing a file in `data/knowledge` has to know which version reads it. The list above answers that
  for 27 September 2026. `data/README.md`, added the same day, keeps that list
  for every file in `data/`.
- `DESIGN.md` describes the shared arrangement in its opening, because it was written then. Its header says
  so, and the two sentences that describe the arrangement now point here.
