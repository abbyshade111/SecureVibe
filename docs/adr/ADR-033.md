# ADR-033: CVSS v4 scores, computed with FIRST's own tables

**Status:** proposed. Claimed on 5 October 2026 by session securevibe-e9, at the owner's asking to keep working off
the backlog, for the deep review's improvement 4.

**Governs:** `crates/sv-check/src/cvss.rs`. A pull request that changes it changes this record too, or says in its
description why it does not (`docs/adr/README.md`).

## Context

`sv audit` and `sv report --advisories` rate a known vulnerability by the CVSS vector its advisory carries
(`crates/sv-check/src/cvss.rs`). Only v3.0 and v3.1 vectors are scored; a v4 vector reads as "no rating `sv` can
read", and the finding is shown as medium with that said. The deep review counted 2,340 OSV records that carry only
a v4 vector. CVSS v4 is not a formula: a vector is placed in one of 270 groups ("macrovectors"), each with a score
FIRST's experts assigned, and the score is then moved within the group by how far the vector is from the group's
most severe one. The table of 270 scores cannot be derived; it has to be copied.

## Decision

- **v4 vectors are scored with the tables of FIRST's reference calculator** (`FIRSTdotorg/cvss-v4-calculator`,
  BSD-2-Clause), copied into `sv` mechanically from a named commit, with the copyright notice and license
  kept. The scoring follows that calculator's `cvss_score.js` step for step.
- **Held against the reference itself:** a few hundred vectors are scored by the reference calculator's own
  JavaScript, and the pairs are kept as test data; `sv`'s score must equal every one.
- **Base and threat metrics only**, as published in advisories; environmental metrics, which describe a
  deployment, take their defaults, as the v3 scoring leaves them out.
- A vector that is not a whole v4 base vector is not scored, as before.

## Consequences

- An advisory with only a v4 vector gets its own rating, not a placeholder medium.
- A third party's data is in the code, under its license, and is updated by copying again from a named commit.
