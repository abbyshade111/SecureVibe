# ADR-075: A tool action the AI took, written down with its argument (C12.4.2, in part)

**Status:** proposed, 9 October 2026, with the backlog claim (0085, part 22); to be accepted in the pull request that
builds it. Asked for by the owner ("please go ahead"). Written by session paper-facts.

**Governs:** `crates/sv-check/src/ai.rs`, where the check this record adds, probe.ai-tool-action-logged, reads the app's
output beside the other output checks (ADR-071, ADR-073 and ADR-074 govern the same file). A pull request that changes
what it says about this changes this record too, or says in its description why it does not (`docs/adr/README.md`).

## Context

AISVS C12.4.2 (level 2) reads: "Verify that audit logs capture security-critical proactive actions, including approver
identity, timestamp, action parameters, and decision outcomes." Nothing in StackVet speaks to it. When the app gives
its model tools from an MCP server, the AI checks' control question has the test model ask for the test tool
`sv_lookup` with the message's tag as its argument, and the test MCP server records the call; the tag exists nowhere
else but in that message and that call.

## Decision

- **Read after the run,** when the control's call reached the test MCP server: a line of the app's output naming
  `sv_lookup` and carrying the tag as the call's argument. A line that carries the tag only inside the person's message
  as it was logged (`SV-PROBE-MCPPLAIN-` and the tag) does not count: that records the message, not the action.
- **Credited, marked in part (ADR-053),** when there is such a line: an action the AI took, with its parameter. The
  credit says whether the line also has a timestamp. The action is a read-only lookup, not a security-critical one, and
  no approver or outcome is seen, so the credit says that too.
- **Never a finding:** actions may be audited in another system. Said when no such line is there, and when the control
  call never reached the tool.
- **Not asked** without an MCP server named in `mcp-url-env`.

## Alternatives considered

- **The app's own record tool (`record-tool`).** Not here: its argument is a record id the app also writes in ordinary
  request logs, so a line carrying it does not show the action was audited.
- **Full credit.** Rejected for the reasons above.
