# ADR-058: A private set of pages for the owner to read `sv`'s documentation, in the home folder, without the paper

**Status:** accepted, 8 October 2026, in the pull request that builds it. Asked for by the owner that day, who chose
where it lives and what it leaves out when asked (backlog, "A private page for the owner to read all of `sv`'s
documentation"). Written by session securevibe-e2.

**Governs:** `tools/docs_page.py`. A pull request that changes it changes this record too, or says in its description
why it does not (`docs/adr/README.md`).

## Context

`sv`'s documentation is some ninety Markdown files: the design, the backlog, the guide, the decision records, and the
prompts. Read as plain text they are hard going, and nothing links one to another in a way a browser follows. The owner
asked for "a private page (just for me on this computer) that makes it easy for me to navigate through all the
documentation and view it", and, asked where it should live and whether the paper's drafts belong in it, answered:
"home folder for the docs page, and do not include the paper drafts please".

## Decision

- **A script in `tools/`, not a command of `sv`'s.** It is for the owner, who works on `sv`, not for the people who use
  it, so it stays out of the program.
- **Written to `~/securevibe-docs/`**, outside the repository, so it is never committed or published. It refuses a
  place inside the repository, and a folder that is not its own; it marks its own folder, and on a later run removes
  only the pages it wrote for documents that are gone.
- **The documents git tracks**, less `docs/paper/` (the owner's choice), the example apps, and the code's folders. A
  file git does not track, such as `.env` or anything in `target/`, is never read.
- **A Markdown reader of its own**, in the script, for what these documents use. Python's standard library has none,
  and a dependency was not wanted for a page only the owner reads. Anything written as HTML in a document is shown as
  text.
- **Nothing fetched.** Every page carries its own style. The index has a search box, whose short script reads an index
  of the documents written into the same page; that script fetches nothing, and the index holds no `<`, so text the
  documents quote, such as `<script`, cannot end it early.

## Alternatives considered

- **Inside the repository, in a folder git ignores:** closer at hand, and one `git add -f` away from being committed.
  The owner chose the home folder.
- **`pandoc` or Python's `markdown`:** better at Markdown's corners, and a dependency to install and keep up to date
  for one private page. Not chosen; the script's own reader is checked by `--self-test` and by
  `crates/sv-cli/tests/docs_page.rs`.
- **Publishing it** (GitHub Pages, or an artifact): not private, which is what was asked for.

## Consequences

- The pages show the documents as they are in the owner's copy, and are out of date until the script is run again
  after a pull.
- Markdown the reader does not know shows as plain text rather than as the formatting meant. The documents use a small
  part of Markdown, and the self-test covers that part.
