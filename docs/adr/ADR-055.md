# ADR-055: Two checks stop resting on one sample: cross-site access asks the private pages, and a common password is three

**Status:** proposed, 7 October 2026, with the backlog claim. Decided by the owner on 7 October 2026 ("go ahead with the
next steps from the recipe trial"), from two faults the recipe trial found (`docs/prompts/library-trial/recipe.md`;
BACKLOG, "`probe.cors-any-origin` asks only the health path" and "`probe.common-password-accepted` rests on one
word"). The pull request that builds it makes it accepted.

**Governs:** `crates/sv-check/src/signed_in/passwords.rs` (which common passwords are tried, and what earns the
credit). The pull request that builds it adds the file that asks the private pages with another site's Origin. A pull
request that changes what these say about this changes this record too, or says in its description why it does not
(`docs/adr/README.md`).

## Context

- `probe.cors-any-origin` (V3.4.2) sends another site's `Origin` to the health path alone. The case it exists for is a
  signed-in page or JSON API that lets any site read it with the person's cookie; it never asks one. In the recipe
  trial the brief asked for a JSON API for a friend's phone app, and the check could not reach it.
- `probe.common-password-accepted` (V6.2.4) tries one password, `123qweasdzxc`. In the recipe trial, lists written
  from memory passed when they held that word (one of 443 entries) and failed when they did not (one of 20,340). Its
  credit says whether one word was refused.

## Decision (proposed)

- **Cross-site access is also asked where it matters:** the first test user, signed in, opens each `private` page with
  another site's `Origin`, judged as the health path is. A page that echoes that origin is a finding. Nothing more is
  credited: the credit from the health path is unchanged, and a finding outranks it.
- **A common password is three:** `123qweasdzxc` (line 1,238 of the list), `1q2w3e4r5t6y` (2,018), and `qwerty123456`
  (2,744), each 12 characters of digits and lowercase letters, so the one random control of that shape still shows a
  refusal is about the word. Any accepted is a finding naming it; the credit needs all three refused and the control
  accepted. Two more sign-ups a run.

## Alternatives considered

- **Mark the common-password credit "in part" (ADR-053) and leave one word.** Says the weakness without fixing it.
- **Words of other shapes,** each with a control of its own: more varied, and twice the sign-ups. The three chosen are
  keyboard patterns, which a list written from memory is likeliest to hold, so passing all three remains a low bar; it
  is no longer a matter of one word.
