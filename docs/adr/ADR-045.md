# ADR-045: The app's own tools are called in a loop only when the owner marks them read-only

**Status:** accepted, 7 October 2026. The decision itself is the owner's, of 6 October 2026 ("I agree with all your
recommendations"). It is recorded here because it had no record, proposed with the backlog claim (#871), and built as
proposed (DESIGN, "An AI agent's limit, asked through the app's own read-only tool").

**Governs:** `crates/sv-manifest/src/lib.rs` (the record tool's read-only setting). The gate itself, calling the tool
in a loop only when it is marked read-only, is in the AI checks' file in `sv-check`, which is not listed here, since it
is changed often for other reasons; it names this record beside the gate. (Said on 8 October 2026, after the second
documentation review.) A pull request that changes what these say about it changes this record too, or says in its
description why it does not (`docs/adr/README.md`).

## Context

C9.1.2 (AISVS) asks that each run of an AI agent has a budget the app enforces. `sv run` asks it by having the test
model call a tool again after every result, up to 40 rounds (`MCPLOOP`, DESIGN "An AI agent with no limit on its tool
calls"). It uses the test MCP server's own tool, `sv_lookup`, which reads nothing and changes nothing, so only apps
that take tools from an MCP server are asked.

An app's own tools, the ones the model can call inside the app (named in `[stack.run.ai] record-tool`), may change
data: send an email, write a record, spend money. Calling one 40 times in a row on `sv`'s copy of the app could still
send 40 emails, or fill a database the run then reads. `sv` cannot tell from the outside which tools only read.

## Decision

- **A new setting, `read-only = true`, on the record tool.** The owner, or the AI tool on the owner's behalf, says the
  tool only reads. Without it the tool is never called in a loop, and the report says so.
- **When marked, the loop question is asked through it** as the MCP one is: the test model asks for the app's own tool
  again after every result, up to the same cap; the same rules for credit, finding, and not assessed apply. It is
  asked only after the record-tool question has shown the tool works.
- **The mark is the owner's word, not evidence.** It decides only whether the tool may be called; nothing is credited
  for it.

## Alternatives considered

- **Calling any named tool in a loop.** It would reach more apps and could change their data many times over, which
  `sv` does not do to an app it has been handed (ADR-038's reasoning for the SQL probe applies).
- **Guessing read-only from the tool's name** (`get_`, `find_`, `search_`). A name is a guess, and a wrong guess
  writes data.
