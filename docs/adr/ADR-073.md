# ADR-073: Token use recorded for each user, found in the record of one model call (C12.2.5, in part)

**Status:** accepted, 9 October 2026, in the pull request that builds it; proposed with the backlog claim (0085, part
20). Asked for by the owner ("please continue whenever you're ready"). Written by session paper-facts.

**Governs:** `crates/sv-check/src/ai.rs`, where the check this record adds, probe.ai-token-use-attributed, reads the
same line as probe.ai-call-log-session (ADR-071 governs the same file). A pull request that changes what it says about
this changes this record too, or says in its description why it does not (`docs/adr/README.md`).

## Context

AISVS C12.2.5 (level 2) reads: "Verify that token usage is tracked at granular attribution levels including per user,
per session, per feature endpoint, and per team or workspace." Nothing in StackVet speaks to it. The AI checks find
the line the app wrote for one model call by the token counts the test model reported for it, which are random and
different every time, and judge it for C12.1.3 (what the record holds) and C12.1.1 (whose session it was in).

## Decision

- **Credited, marked in part (ADR-053),** when that line, which carries the call's token counts, also names the
  signed-in test user the AI feature was asked as, or carries a user or session field: token use tracked per user or
  per session. The credit says which. Per feature endpoint and per team or workspace are not seen.
- **Never a finding:** the counts may be attributed in another record or another system.
- **Not assessed, and said,** when the AI feature was asked without signing in, or the call's line was not found, or
  it names no user and no session.

## Alternatives considered

- **Add C12.2.5 to `probe.ai-call-log-session`.** Rejected: that credit is for the session context of a logged
  interaction (C12.1.1); this one is for token use tracked per user, and is in part, so the two are kept apart.
- **Full credit for a line with every attribution.** Not here: a team or workspace cannot be told apart from other
  fields without knowing the app.

## Where the build differs from the proposal

- **Said when no line carried the counts, and when the app wrote nothing at all,** as well as when it was asked
  without signing in or the line names nobody, so C12.2.5 is spoken to whenever the AI checks ran a model call.
- **The fields counted per user and per session are written out:** `user`, `user_id`, `userid`; `session`,
  `session_id`, `sessionid`, `conversation_id`, `conversationid`.
- **Not run end to end** with an app under `sv run`, which needs Docker.
