# ADR-072: The app's log files served to anybody who asks (V16.4.2)

**Status:** accepted, 9 October 2026, in the pull request that builds it; proposed with the backlog claim (0085, part
19). Asked for by the owner ("please continue to work through and pick up new items as you merge"). Written by session
paper-facts.

**Governs:** `crates/sv-check/src/probes.rs`, where the check this record adds, probe.log-file-served, asks beside
the checks for exposed documentation and monitoring pages (ADR-047 and ADR-056 govern the same file). A pull request
that changes what it says about this changes this record too, or says in its description why it does not
(`docs/adr/README.md`).

## Context

ASVS V16.4.2 (level 2) reads: "Verify that logs are protected from unauthorized access and cannot be modified."
Nothing in StackVet speaks to it. A log file left where the web server serves files, or a framework's log path
answered by a catch-all route, hands sessions, email addresses, tokens and errors to anybody who asks for it. The
anonymous probes already ask for documentation and monitoring pages left open (`probe.docs-or-monitoring-exposed`);
no log path is among them.

## Decision

- **Asked, not signed in,** for the addresses frameworks commonly leave logs at: `/logs/`, `/log/`, `/logs/app.log`,
  `/log/production.log`, `/storage/logs/laravel.log`, `/error.log`, `/debug.log`, `/npm-debug.log`, and
  `/var/log/app.log`.
- **A finding (high)** when one is answered 200 with lines that read as a log: at least three lines that each start
  with a timestamp, or carry a level word (`INFO`, `WARN`, `ERROR`, `DEBUG`) beside a date. A page the app answers
  every address with, its own home page or a "not found" page sent as 200, does not read as a log.
- **Only ever a finding:** a few guessed addresses cannot show that no log is served, so it is listed as one that only
  finds.
- **Reading only.** "Cannot be modified" is not tried: writing to a log through the web is not something a probe can
  ask for safely.

## Alternatives considered

- **Any 200 at a log path.** Rejected: many apps answer every address with their own page.
- **The static half** (a log handler writing under a served folder). Left for a later item: it needs each framework's
  served folder.

## Where the build differs from the proposal

- **The common log format's time is read anywhere in a line,** since in an access log it follows the client's
  address; the first version looked only at the start of each line and missed it.
- **HTML is never a log,** so a page the app answers every address with, even one listing dated items with a word a
  log also uses, is left alone.
- **The test of how many requests the anonymous probes send counts the nine** log addresses.
