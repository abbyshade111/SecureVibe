# ADR-022: Whose word counts, and at which tier

**Status:** accepted. Built from 26 to 27 September 2026, chiefly in #175 (the AI coding tool's answers as a tier of
their own, the interview, and checks made by hand) and #242 (a person confirming what the tool said), with the
security notes' `Written by:` line in #239, and the answer-recording tool on 4 October 2026 (#539). Written down here
on 4 October 2026, because the first weekly review of the decision records found that `docs/adr/README.md` pointed to
v1's ADR-006 for this and that `sv`'s own statuses had no record (BACKLOG, "Records owed", item 2).

**Governs:** `crates/sv-check/src/design.rs`, `crates/sv-check/src/hand.rs`, `crates/sv-check/src/notes.rs`,
`crates/sv-check/src/confirm.rs`. A pull request that changes any of these changes this record too, or says in its
description why it does not (`docs/adr/README.md`).

## Context

Some requirements can be checked by reading the code or asking the running app. Many cannot: they ask how the app is
built, what its rules are, or for something a person must look at, such as the padlock on the live site. For those,
`sv` has only what somebody says, and it is usually the owner's AI coding tool that writes it down, in
`securevibe.toml` and `security-notes.md`, because the owner is not a programmer.

v1's ADR-006 set the rule that carries over: AI review alone is never a pass, and a requirement only a person can
check never passes on its own. `sv` needed more than that rule. It needed to say whose word each answer is, and how
much it is worth.

On 27 September 2026, in the owner's first run in VS Code, the tool wrote nine of the thirteen sections of the notes
from the code and marked each with its own italic line. `sv` threw that line away along with its own italic lines,
and reported all nine as *documented by the owner*.

## Decision

Every answer is credited at the tier of whoever gave it, and an answer that does not say who gave it is the tool's.
The tiers, as the report names them (`Status` in `crates/sv-report/src/lib.rs`), with the ones that rest on
somebody's word below *checked*:

- **checked**: an automated check, of the code or the running app.
- **documented by the owner**: a section of `security-notes.md` under `Written by: owner`.
- **checked by hand by the owner**: a `[checked-by-hand]` entry by the owner, saying what was done (`how`) and when
  (`on`); it counts for 90 days.
- **attested by the owner**: a design answer in `securevibe.toml` with `by = "owner"`.
- **stated by the AI coding tool**: the same answers with `by = "ai-tool"` or `Written by: AI coding tool`, or with
  nothing saying who. In the project's words, "it is the author grading its own work".
- **not verified**: nothing at all.

Rules that hold it together:

- **No mark means the tool's.** "The file is usually written by the tool, so crediting the owner on nobody's say-so is
  the direction that overstates" (the owner's decision, 27 September 2026, for the notes; the design answers already
  worked this way). A mark naming anyone else is named as unreadable, not guessed at.
- **A person can confirm the tool's answer** (`confirmed = { by, on, ... }`, `crates/sv-check/src/confirm.rs`). It then
  counts at the person's tier and is shown as confirmed, because writing `by = "owner"` "would say they gave the answer;
  they checked somebody else's". The tool cannot confirm its own answer, and a confirmation pointing at a file lapses
  when the file changes after it.
- **A person's word never settles a test.** *Attested*, *checked by hand*, and *stated* stay on the list of tests to
  write, and a finding or a check outranks them: "Letting the word retire the test is how *attested* would quietly
  become *checked* with nobody deciding to make it so."
- **What the tool records is the tool's.** Since 4 October 2026, `securevibe_record_answer` writes every answer it
  records as `Written by: AI coding tool` and offers no way to say "the owner"; the owner changes the line
  themselves (the owner's decision that day).

## Alternatives considered

- **Letting `by = "owner"` stand for a confirmation.** Set aside for the reason quoted above: it would credit the owner
  with an answer they only checked.
- **A named reviewer above the owner.** Set aside: "`sv` cannot tell who anyone is", so no name can outrank another.
- Nothing else is written down as considered.

## Consequences

- An answer the tool gave is asked again in the interview until a person gives or confirms it, so the owner sees what
  is still the tool's word.
- **`sv` cannot tell who typed a name.** Every tier above *stated* rests on a mark anybody with the file can write; what
  `sv` does is make the rule plain to the tool, refuse to write the owner's mark itself, and show every answer with its
  source. Nothing in a file can stop a tool that edits it from writing `Written by: owner`.
- A file changed on the same day as the confirmation that points at it is not seen as changed.


## Later, 4 October 2026: the owner's tiers need a seal

ADR-026 changes part of this record. *Documented by the owner*, *attested by the owner*, and *checked by hand by the
owner* now need the owner's answer to have been recorded through `sv review`, which seals it; `by = "owner"` or
`Written by: owner` written into a file any other way counts as *stated by the AI coding tool*. A confirmation counts
only when sealed in the same way. The tiers and their order are unchanged. The consequence above, "Nothing in a file can
stop a tool that edits it from writing `Written by: owner`", still holds of the file; what changed is that writing it no
longer earns the owner's tier.
