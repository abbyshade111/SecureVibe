# ADR-013: Reports as PDF files, written by SecureVibe

**Status:** accepted — 25 September 2026.

The owner agreed the direction: a PDF that does not depend on the person's browser.

## Context

Each report was written as HTML, JSON and Markdown. "Save as PDF" loaded the HTML in a hidden frame and opened the
browser's print dialog, so no PDF existed until a person made one, one report and one dialog at a time, and what came
out depended on the browser and its settings. The backlog asked whether depending on the owner's installed browser was
acceptable. It is not: the person who receives a hand-off pack or an appendix should get the reports as files.

## Decision

SecureVibe writes the PDF itself, at report time, beside each HTML report (`overview`, `compliance-report`,
`security-report`, `going-online`), from the HTML the renderers already produce. `server/src/reports/pdf/` reads that
HTML (a fixed set of tags SecureVibe writes; not a general HTML reader), lays it out on A4 pages and writes the file:
tables keep their header row on every page and split long rows across pages, collapsed sections are opened, rows the
web page hides until asked are left out, chapters become bookmarks, and every page carries the title and "Page n of N".
The results page downloads the file; a run made before this existed gets its PDF made on request from its saved HTML.

## What it costs, stated plainly

* **Only Western European letters and common punctuation can be shown.** The file uses the five fonts every PDF reader
  has (Helvetica in three forms, Courier), so no font is bundled. Emoji are dropped (each status badge also carries its
  word, so nothing is lost); a few symbols become ASCII; any other character, such as an app named in Japanese, prints as
  `?`. The HTML report remains the complete version, and the results page says so beside the download.
* **Paper size is a setting** (Settings, "Paper size for PDF reports"): US Letter by default, or A4. New PDFs are written in the
  size set when the check runs. A PDF downloaded from the results page is made again in the size set now when the saved file
  is on the other one, so the choice applies to older checks too; the saved file is left as it was. The PDFs inside the
  hand-off pack and the all-apps zip are the saved files, so they keep the size of the day.
* **The layout is plain.** No colored panels beyond a tint and a bar, no images, no charts, text left-aligned.
* **We own the writer.** About a thousand lines and their tests, in place of a dependency.

## Alternatives considered

* **A browser engine at report time** (the owner's installed Chrome, or a bundled headless one). Rejected: it is the
  dependency the backlog asked about, it differs between machines, and a bundled one is a large download that has to be
  kept patched for a tool that does not run untrusted content.
* **A PDF library** (pdfkit, pdfmake). Rejected for now: a new package tree in a project that disables install scripts,
  enforces a minimum package age and checks its own dependencies, to draw text and tables. It would also bring embedded
  fonts and full Unicode, which is the one thing the writer above cannot do; if the character limit above proves to
  matter to owners, this is the change to make, and the layout code would stay.
* **Keeping the print dialog.** Rejected: no file exists until someone makes it.

## Consequences

* `ArtifactRef.format` gains `pdf`; the reports folder, the across-apps zip and the hand-off pack carry the PDFs with no
  further change, because they pack the folder.
* A test reads each fixture report back from the PDF and checks that every ordinary word of the web page is printed whole,
  that nothing runs past the margin, and that no character would print as `?`, so a report that starts using a character
  the fonts lack fails a test instead of printing wrongly.
* The reports' frame policy is now `frame-ancestors 'none'`: the hidden print frame was the only thing that framed them.
