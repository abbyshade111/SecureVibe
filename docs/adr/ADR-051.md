# ADR-051: The tests must pass before a pull request merges into main, and every commit on main is tested

**Status:** accepted, 7 October 2026, in the pull request that changes the workflow; proposed the same day with the
backlog claim. Decided by the owner on 7 October 2026: "I definitely want the tests required before merging and
thought I had turned that on" (`docs/GAP-ANALYSIS.md`, 7.1). The required check itself waits on the owner (below).

**Governs:** `.github/workflows/rust.yml`. A pull request that changes it changes this record too, or says in its
description why it does not (`docs/adr/README.md`).

## Context

On 7 October 2026 the only check required before merging into `main` was "Decision records" (the ruleset "Main - ADR
Check"). The `test` job of `rust.yml` (formatting, lints, and the whole test suite) was not required, so a pull
request could merge with it failing or still running: #871 and #873 did that day. And on `main`, 19 of the last 50
runs of `rust.yml` were cancelled before they finished: the concurrency group was one per branch, and when a run is
already waiting, GitHub cancels the waiting one in favor of the newest, whatever `cancel-in-progress` says. So about
four in ten commits on `main` were never tested there.

## Decision

- **`test` is a required check on `main`**, held to GitHub Actions' own run (app 15368) so nothing else can satisfy it.
  This is a repository setting. A Claude Code session cannot change repository settings through its GitHub
  connection, so the owner makes it; until then this record says what was decided, not what is in force.
- **Every commit on `main` is tested.** `rust.yml`'s concurrency group on `main` is the commit, not the branch, so no
  run there waits behind another and none is replaced. Branches keep one group each, and a newer push still cancels
  an older run, since only the newest commit of a pull request can be merged.
- **The image is still published once at a time and newest last.** The publishing job has its own group on `main`,
  never cancelled while it runs; a waiting one is replaced by a newer one, which only skips publishing an image that
  is already out of date.
- "Up to date with `main` before merging" stays off: with several sessions merging each hour it would re-run every
  pull request after every merge. The tests on `main` itself catch two changes that pass apart and fail together.

## As built (7 October 2026)

- `rust.yml`'s group is `rust-<commit>` on `main` and `rust-<branch>` elsewhere. The publishing job has the group
  `rust-publish-main`, and moves the `latest` tag only when its commit is still the newest on `main`, since runs on
  `main` can now finish out of order; the commit's own tag is always pushed.
- The session that built this tried to add `test` to the ruleset and was refused: its GitHub connection may not write
  repository settings. The owner adds it on GitHub: Settings, then Rules, then Rulesets, then "Main - ADR Check";
  under "Require status checks to pass", add `test` from GitHub Actions, and save.
