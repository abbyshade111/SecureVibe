# ADR-064: A tool that does not answer, and C9.1.1 checked in part

**Status:** proposed, 9 October 2026, with the backlog claim (0029, part 9: C9.1.1's per-tool quotas and timeouts); to
be accepted in the pull request that builds it. Asked for by the owner ("go ahead with part 9, yes"). Written by
session paper-facts.

**Governs:** `crates/sv-run/assets/model-provider.mjs`, where the test tool holds its answer (ADR-042 governs the same
file, and has a Later entry), and the check this record adds to the AI checks, probe.ai-tool-timeout, in the AI
checks' file in sv-check, which is not listed here, since it is changed often for other reasons (as ADR-045 says of the
same file). A pull request that changes what these say about this changes this record too, or says in its description
why it does not (`docs/adr/README.md`).

## Context

AISVS C9.1.1 (level 1) reads: "Verify that per-tool quotas and timeouts (e.g., CPU, memory, disk, egress, and
execution time) are enforced." Nothing in StackVet speaks to it. C9.1.2's budget is asked already: the stand-in model
asks for a tool again and again, and an app that stops it is credited (`probe.ai-agent-unbounded`). Of C9.1.1's list,
only execution time can be seen from outside the app: a tool's use of CPU, memory, disk and network happens inside
the app's own process or the tool's, where a running-app check cannot look.

The stand-in service already holds an answer back to see whether the app waits for ever on its AI service
(`probe.ai-service-hang-handled`, V16.5.2), and already serves a test tool over MCP (`sv_lookup`). A tool that holds
its answer is the same question asked of the tool.

## Decision

- **The question.** When the app offers the test MCP tool to its model, one message has the stand-in model ask for
  `sv_lookup`, and the tool holds its answer for 40 seconds, as the held AI message is held.
- **Credit, in part.** The app answering that message by itself within the 15 seconds StackVet waits on any request,
  while the tool's call is shown to have reached the tool and to be held still, is a time limit on that tool: C9.1.1
  is credited, marked in part (`Verified::in_part`, ADR-053), since execution time is one of the five things it names
  and one tool was tried.
- **No finding.** No answer within 15 seconds says nothing either way: an app whose own limit is longer cannot be told
  from one with none. The check is listed as one that only ever credits.
- **Not asked** when the app does not offer the test tool, and said so; the hold is waited out afterwards, as the held
  AI message's is, so an app still waiting is free for the checks after it.

## Alternatives considered

- **A finding when nothing came back within 15 seconds.** Rejected: it would call a longer limit no limit.
- **Full credit for C9.1.1.** Rejected: one tool and one of five resources is part of the requirement, and ADR-053's
  "checked in part" exists so a partial check never reads as the whole.
- **The app's own tool (`record-tool`), held.** Not possible: StackVet does not serve the app's own tools, so it
  cannot make one of them hang.
