# ADR-017: `sv` never writes the app's code

**Status:** accepted. Decided with `sv`'s design ("No wizard": the person builds the app in their own AI
coding tool), and written down here on 27 September 2026.

## Context

v1 wrote the app. An AI generation agent extended a hardened template, and because that agent could write and
run files, it worked inside a fence of its own: allow-listed paths, validated tool inputs, and screened tool
output (v1's `CLAUDE.md`).

`sv` does not build the app. The person builds it in whatever AI coding tool they choose, and `sv` checks the
result afterwards.

## Decision

`sv` writes no code the app runs. It has no generation agent, so v1's fence around that agent has no
successor here, and none is needed.

What `sv` does write, each only when asked, by the owner's command or through its MCP server:

- `security-notes.md` (`sv notes`): the questions only the owner can answer, kept with their answers.
- A section of `AGENTS.md` between `sv`'s markers (`sv rules`): security rules for the AI coding tool to
  follow while it writes. The rest of the file is left as it was.
- The reports (`sv report`, into `securevibe-report/` unless told otherwise), in a folder marked so that the
  next check does not read it as the app's code, and a zip of the app with its report (`sv bundle`).

`sv init` writes nothing: it prints the `securevibe.toml` specification, and the owner's AI tool writes the
file. Everything in the list is read by a person or by the AI tool, and none of it is part of the running app.

Two other limits stand on their own, and this decision does not touch them:

- **Running the app is still fenced** (`sv-run`): the app runs in a container with no network beyond
  loopback and `sv`'s own stand-in services, and nothing published to the owner's computer.
- **`sv` opens no network connection of its own** (`CLAUDE.md`), with one exception the owner asks for by
  name: `sv probe <address>` makes at most four read-only requests to that address, through `curl`, and
  one DNS query to this computer's resolver.

## Alternatives considered

- **Offer fixes as code.** `sv` knows where a finding is and could write the change. That would make `sv` a
  second author of the app, beside the person's own tool, and would bring back everything the fence existed
  for. A finding carries a plain-language fix for the person, or their tool, to make instead.

## Consequences

- A fix is always made by whoever wrote the app, and the next `sv` check is what shows it worked.
- `sv` needs no guard against its own output breaking the app, and none against a model writing where it
  should not.
- A future feature that writes into the app's folder should be checked against this record. `AGENTS.md`
  is the nearest case so far: it steers the AI tool that writes the code, and writes no code itself.
