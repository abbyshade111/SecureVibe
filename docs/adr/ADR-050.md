# ADR-050: The app's own tests are a tier of their own, below an automated check

**Status:** proposed, 7 October 2026, with the backlog claim. Decided by the owner on 7 October 2026 ("go ahead with
the first four"), the first of the four places to start in `docs/GAP-ANALYSIS.md` (1.1). To be made accepted in the
pull request that builds it, saying where the build differs from this plan.

**Governs:** `crates/sv-check/src/suite.rs` (which test names credit which requirements),
`crates/sv-report/src/lib.rs` (the statuses and their order). A pull request that changes either changes this record
too, or says in its description why it does not (`docs/adr/README.md`).

## Context

`sv` asks the AI coding tool to write tests that name the requirements they show (`sv init`'s specification, the
feature briefs), and runs the app's test command under `sv run`. When the command passes, every requirement id named
in a test file has been credited as *checked*, the same status as `sv`'s own checks, and the short version calls it
"an automated check looked and found nothing wrong". But the AI coding tool writes both the tests and the command, and
the credit has rested on the name alone: any file under `tests/`, a Markdown note among them, a comment.

ADR-022 ranks the AI coding tool's answer lowest (*stated*) because it is "the author grading its own work". Through a
test the same author's work reached the highest tier. A passing test is more than an answer, since it ran and the app
did what the test asked; but what the test asked is the author's choice, and nothing here reads whether it asks what
the requirement asks.

## Decision

- A new status, **tested by the app's own tests**, between *checked* and *documented by the owner*. A requirement
  whose only evidence is the app's own tests has it. It never becomes *checked*, and the short version says whose
  tests they are ("your app's own tests, written by your AI coding tool, passed") apart from what `sv`'s checks did.
- **A threat is never settled by it alone**, as it is not by any other tier below *checked*.
- **Only code is read.** A requirement id counts only in a file of a language `sv` reads; a Markdown or text file under
  `tests/` credits nothing.
- **Requirements a test cannot show** (documentation, deployment, process: the list the report already keeps of ids
  left off "tests to write") are never credited by the app's tests; a test naming one is supporting evidence only.

## Consequences

- Reports with app tests show fewer *checked* requirements and a new row; nothing previously *not verified* changes.
- Not done here, and left on the backlog: reading the test report even when the suite passes, so only cases the
  report names as passed count; and showing that a test fails when the protection it names is removed.
