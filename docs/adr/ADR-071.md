# ADR-071: The AI service's failure found in the app's own output (V16.3.4, in part)

**Status:** accepted, 9 October 2026, in the pull request that builds it; proposed with the backlog claim (0085, part
18). Asked for by the owner ("please continue to work through and pick up new items as you merge"). Written by session
paper-facts.

**Governs:** `crates/sv-check/src/ai.rs`, where the AI checks read the app's output for what it recorded and where the
check this record adds, probe.ai-service-failure-logged, sits beside the others that do. A pull request that changes
what it says about this changes this record too, or says in its description why it does not (`docs/adr/README.md`).

## Context

ASVS V16.3.4 (level 2) reads: "Verify that the application logs unexpected errors and security control failures such
as backend TLS failures." Nothing in StackVet speaks to it. The AI checks make the test model fail one message on
purpose, answering 500 with an error in the service's own shape whose message carries `SVERR` and the message's tag,
which nothing else in the run produces; and after the run they read what the app wrote to its output for the record of
its model calls (C12.1.3) and of the injection it was sent (C12.2.1).

## Decision

- **Credited, marked in part (ADR-053),** when the marker from the failed message is in the app's output: an outside
  service failing, which the app did not expect, was written down. One kind of failure, of one service, was tried.
- **Never a finding:** an app that logs to a file or a logging service writes nothing to its output and is not logging
  any less for it, as the other output checks say.
- **Not assessed, and said,** when the failure was not caused (the message did not reach the test model), and when the
  marker is not in the output.
- **Not asked** without an `ai` section.

## Alternatives considered

- **A 5xx from any probe, with a marker in its address.** Not here: whether an answer of 500 was an unexpected error or
  a deliberate one cannot be told, and the marker in the address is logged by an app that logs every request, error or
  not.
- **Full credit.** Rejected: the requirement asks for unexpected errors and security control failures generally.

## Where the build differs from the proposal

- **The failure question hands the failed message's tag on,** as a new field of the markers the output checks read,
  and the output is searched for `SVERR` with that tag, so another message's error, or `SVERR` alone, credits nothing.
- **It is asked first among the output checks,** before any of them can return, so V16.3.4 is said whenever the AI
  checks ran, including when the app wrote nothing to its output.
- **Not run end to end** with an app under `sv run`, which needs Docker.
