# ADR-031: A `not-the-app` list that would set apart all of the app's code is not used

**Status:** accepted. Claimed on 5 October 2026 by session securevibe-e9, at the owner's asking to keep working
off the backlog, for the deep review's R12 (medium to low, reproduced), and built the same day in branch
`claude/securevibe-e9-r12` (DESIGN, "A `not-the-app` list that would set apart all the code is not used").

**Governs:** `crates/sv-scan/src/lib.rs`, `crates/sv-cli/src/main.rs` where they read `[repository] not-the-app`.
A pull request that changes how that list is applied changes this record too, or says in its description why it
does not (`docs/adr/README.md`).

## Context

`[repository] not-the-app` in securevibe.toml names folders that are not the app, such as examples and test
fixtures (DESIGN, "Folders the manifest says are not the app", 27 September 2026). What is in them is still
checked and counted, but it is no longer evidence of what the app uses, so it cannot switch requirements on.
securevibe.toml is written by the AI coding tool. An entry such as `src`, or `*`, in an app whose code all lies
under `src` or one folder down, takes every file of the app's code out of that evidence. Requirements that the
code would have shown to apply then read "does not apply", and the report's only sign is a gap line that names
the folder. The list refused only an entry that named the whole app outright (`.`, `*` alone, an empty string).

## Decision

- **When the list, taken together, would leave none of the app's code files outside it, the whole list is not
  used.** Code files are those in a language `sv` reads (`Listing::code_files`). Every folder is then read as the
  app, as if the list were empty, and the report says why under "What was not examined", with the count. An app
  with no code file at all is not affected, since there is nothing to hide.
- **The whole list, not one entry,** because no single entry need be at fault: `src` and `lib` together can cover
  an app that has code in both.
- **One place decides,** in `sv_scan`, and every command reads the app through it, `sv audit`'s split of its
  packages and the listing of findings with test and sample code included, so no command uses a list another
  refused.
- **When the list is used, the report says how many of the app's code files it set apart,** so a list that leaves
  one file outside is visible too.

## Consequences

- A list that hides all of the app's code can no longer move requirements to "does not apply".
- A list that hides nearly all of it still can. The count in the report is the only guard there; a share past
  which the list is refused would be a guess at what an app's tests and examples weigh.
