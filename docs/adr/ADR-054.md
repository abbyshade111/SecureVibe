# ADR-054: Templates and notebooks are read for what they can hold, and never pass silently

**Status:** accepted, 8 October 2026, in the pull request that builds it. Proposed 7 October 2026 with the backlog
claim. Decided by the owner on 7 October 2026: "yes, go ahead with item 14 as you recommended"
(`docs/GAP-ANALYSIS.md`, 3.6; BACKLOG, item 14).

**Governs:** `crates/sv-scan/src/ecosystems.rs`, `crates/sv-check/src/ast.rs`, `crates/sv-check/src/ast/templates.rs`.
A pull request that changes any of them
changes this record too, or says in its description why it does not (`docs/adr/README.md`).

## Context

`sv`'s code rules give a clean result ("nothing of this kind found") only when every language present in the app was
read: while any is unread, no rule claims anything, because the call it looks for could be in the files nobody read
(ADR-018). A file whose extension `sv` does not know is not counted as a language at all. So `.ipynb`, `.astro`,
`.ejs`, `.erb`, `.hbs`, `.pug`, `.twig`, `.j2`, `.njk`, `.liquid`, `.cshtml`, `.razor`, `.jsp`, and `.sql` were
neither read nor named as unread: a notebook calling `eval` and an Astro page drew nothing, and the clean results stood.

Naming them all unread would be honest, and would withdraw every code rule's clean result from almost every web app,
since nearly all have a template. They are not alike: some can hold any code the language allows, some cannot run code
at all, and some are data.

## Decision

Each kind is read for what it can hold.

1. **Notebooks (`.ipynb`) are read as Python:** their code cells, at the lines they are on in the notebook.
2. **Templates that embed a general-purpose language are unread code:** `.ejs` and `.pug` (JavaScript), `.erb`
   (Ruby), `.jsp` (Java), `.cshtml` and `.razor` (C#), and `.astro` (a TypeScript header). Any of them can hold the
   calls the rules look for, so while one is present and not read, the rules claim nothing, and the report says which
   files kept them from it. Reading the code in them is a later step, starting with Astro's header and EJS's
   `<% %>` blocks, the commonest in AI-built apps.
3. **Templates that cannot run code are read as pages:** `.hbs`, `.mustache`, `.liquid`, `.twig`, `.j2`, `.jinja`,
   `.jinja2`, and `.njk`, as `.html`, `.vue`, and `.svelte` are: the scripts in them are read as JavaScript. Their own
   syntax cannot call a shell, evaluate code, or build a query, so they hold back no rule. What they can do wrong, mark
   a value as safe HTML, is the cross-site scripting checks' question, not these rules'.
4. **SQL files (`.sql`) are named as files no rule reads**, and hold nothing back: the injection rules look at how the
   application's code builds a query, not at a file of SQL.

## Alternatives considered

- **Every one of them unread.** Honest, and withdraws the clean result from nearly every web app for files that, in
  most of them, cannot hold what the rules look for.
- **Every template read as a page.** Keeps the clean result, and claims it over server-side code in `.ejs`, `.erb`,
  and `.jsp` that nobody read: the false pass this project exists to avoid.

## Consequences

An app with an `.ejs`, `.erb`, `.jsp`, `.cshtml`, `.razor`, `.pug`, or `.astro` file loses its code rules' clean
results until that language's template code is read, and the report says so. An app with only logic-free templates
keeps them, and its templates' scripts are now read where before they were not. A notebook's code is now read and
can be found at fault.

## Where the build differs from the plan

- **`.sql` is not given a language.** It is recognized by its extension in the code rules alone, so it does not count
  as code anywhere else: not in the share of the app's code a `not-the-app` list may set apart (ADR-031), and not
  among the files the tools that read every language are handed.
- **A notebook's `%magic` and `!command` lines, and its `%%` cells,** are blanked before Python reads it. They are
  not Python, and `!rm -rf {path}` runs a shell command no rule looked at, so a notebook with any of them counts as
  not fully read, and every rule whose call could be named in them is held back, as for a page whose script did not
  parse. Five magics that only change how the notebook shows or reloads things (`%matplotlib`, `%load_ext`,
  `%reload_ext`, `%autoreload`, `%config`) are blanked and hold nothing back.
- **A notebook whose kernel is another language** (R, Julia) is that language unread, and keeps every rule from a
  clean result. A notebook that is not JSON `sv` can read is a file not opened.
- **The technology scan passes over notebooks and code templates,** as it did before they had names, and reads
  logic-free templates as it reads pages. Counting the templates as not looked in would take a "this app does not
  use X" answer away from every app with one.
- **Semgrep is handed templates and notebooks.** It is handed every file `language_of` names, so its rules for
  `*.erb`, `*.ejs`, `*.pug`, and `*.jsp` now run over an app's templates, and are counted and credited where they ran
  over one (ADR-018, Later, 7 October 2026).

## Later

**8 October 2026: Astro's and EJS's code is read.** The second step decision 2 named, built at the owner's word
("pick your next backlog item"; approved with item 14 on 7 October). `.astro` and `.ejs` are read as pages are, with
their code taken out as Svelte's and Vue's is (`template_code` in `crates/sv-check/src/ast.rs`):

- **Astro:** the `---` header, every `{…}` in the markup outside scripts, styles, and comments, and the page's
  `<script>` elements, all as TypeScript, which Astro compiles them as. A `{…}` may hold JSX, so it is parsed with
  the TSX grammar.
- **EJS:** every `<% %>`, `<%= %>`, and `<%- %>` together, as the one JavaScript program EJS compiles them into, each
  tag starting a statement, so `<% if (a) { %> … <% } %>` reads as `if (a) { … }`; `<%# %>` comments are not code.
  The markup around them is read as a page, with each tag blanked out.

A page whose code cannot all be taken out (a `<%` with no `%>`, a header never closed, a `{` with no `}`), or does not
parse, is named as not fully read and holds back each rule whose call could be named in it, as for Svelte and Vue.
One case is EJS's alone: EJS ends each `<% %>` with a line break, which this cannot add without moving every line
after it, so a `//` comment in one with another tag after it on the same line would hide that tag's code, and such a
page is not read in full. `.pug`, `.erb`, `.jsp`, `.cshtml`, and `.razor` stay unread code.

## Later, 9 October 2026: the readers in a file of their own

The notebook and template readers this record decided moved, unchanged, from `ast.rs` to `ast/templates.rs`
(architecture assessment of 8 October 2026, item 11), and this record governs that file as well. What is read, and
