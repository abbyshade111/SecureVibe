# ADR-054: Templates and notebooks are read for what they can hold, and never pass silently

**Status:** proposed, 7 October 2026, with the backlog claim. Decided by the owner on 7 October 2026: "yes, go ahead
with item 14 as you recommended" (`docs/GAP-ANALYSIS.md`, 3.6; BACKLOG, item 14). To be made accepted in the pull
request that builds it.

**Governs:** `crates/sv-scan/src/ecosystems.rs`, `crates/sv-check/src/ast.rs`. A pull request that changes either
changes this record too, or says in its description why it does not (`docs/adr/README.md`).

## Context

`sv`'s code rules give a clean result ("nothing of this kind found") only when every language present in the app was
read: while any is unread, no rule claims anything, because the call it looks for could be in the files nobody read
(ADR-018). A file whose extension `sv` does not know is not counted as a language at all. So `.ipynb`, `.astro`,
`.ejs`, `.erb`, `.hbs`, `.pug`, `.twig`, `.j2`, `.njk`, `.liquid`, `.cshtml`, `.razor`, `.jsp`, and `.sql` were
neither read nor named as unread: a notebook calling `eval` and an Astro page drew nothing, and the clean results stood.

Naming them all unread would be honest, and would withdraw every code rule's clean result from almost every web app,
since nearly all have a template. They are not alike: some can hold any code the language allows, some cannot run code
at all, and some are data.

## Decision

Each kind is read for what it can hold.

1. **Notebooks (`.ipynb`) are read as Python:** their code cells, at the lines they are on in the notebook.
2. **Templates that embed a general-purpose language are unread code:** `.ejs` and `.pug` (JavaScript), `.erb`
   (Ruby), `.jsp` (Java), `.cshtml` and `.razor` (C#), and `.astro` (a TypeScript header). Any of them can hold the
   calls the rules look for, so while one is present and not read, the rules claim nothing, and the report says which
   files kept them from it. Reading the code in them is a later step, starting with Astro's header and EJS's
   `<% %>` blocks, the commonest in AI-built apps.
3. **Templates that cannot run code are read as pages:** `.hbs`, `.mustache`, `.liquid`, `.twig`, `.j2`, `.jinja`,
   `.jinja2`, and `.njk`, as `.html`, `.vue`, and `.svelte` are: the scripts in them are read as JavaScript. Their own
   syntax cannot call a shell, evaluate code, or build a query, so they hold back no rule. What they can do wrong, mark
   a value as safe HTML, is the cross-site scripting checks' question, not these rules'.
4. **SQL files (`.sql`) are named as files no rule reads**, and hold nothing back: the injection rules look at how the
   application's code builds a query, not at a file of SQL.

## Alternatives considered

- **Every one of them unread.** Honest, and withdraws the clean result from nearly every web app for files that, in
  most of them, cannot hold what the rules look for.
- **Every template read as a page.** Keeps the clean result, and claims it over server-side code in `.ejs`, `.erb`,
  and `.jsp` that nobody read: the false pass this project exists to avoid.

## Consequences

An app with an `.ejs`, `.erb`, `.jsp`, `.cshtml`, `.razor`, `.pug`, or `.astro` file loses its code rules' clean
results until that language's template code is read, and the report says so. An app with only logic-free templates
keeps them, and its templates' scripts are now read where before they were not. A notebook's code is now read and
can be found at fault.
