# ADR-060: One file per design entry

**Status:** proposed, 8 October 2026, with the backlog claim. Asked for by the owner that day ("can you implement your
recommended action of one file per design entry"), from three ways put to them: a `.gitattributes` rule, an action
that merges `main` into conflicted pull requests, and one file per entry. Written by session securevibe-e9.

**Governs:** `docs/DESIGN.md`. A pull request that changes it changes this record too, or says in its description why
it does not (`docs/adr/README.md`).

## Context

`docs/DESIGN.md` is the dated record of every design decision: 296 sections and about a megabyte, each written when
its decision was made and appended to the end. Every session that builds something adds a section there, so any two
open pull requests change the same lines at the end of the file. On 8 October 2026 five pull requests of one session
were each made to conflict four or five times by the others' merges, each time in `DESIGN.md` alone, and auto-merge
stalled until `main` was merged in by hand.

## Decision

Each section becomes a file of its own under `docs/design/`, named by a four-digit number that keeps the order they
were written in, followed by its heading made into a file name. The heading inside is unchanged, so a reference of the
form `DESIGN, "Section title"`, used some 350 times in the code and the documents, still finds its section by a search
of `docs/design/`. `docs/DESIGN.md` keeps its opening and says where the entries are and how to add one. It holds no
list of them: a list that every entry adds a line to would be the same shared lines again.

A new entry is a new file. A script in `tools/` writes one, numbered one past the highest there; two pull requests
open at once may take the same number, which harms nothing, since the names differ and the order among entries of the
same day matters to no one. The same script moves the sections that a branch written before the split added to the old
`DESIGN.md` into entries of their own, once that branch has merged `main`.

## Considered

- **A `.gitattributes` rule (`merge=union`).** Git keeps both sides on a local merge, but GitHub ignores the rule
  when it decides whether a pull request conflicts, so auto-merge would still stall.
- **An action that merges `main` into every conflicted pull request.** Keeps the file whole, but needs a stored token
  that can push and start CI, since the built-in token deliberately cannot, and only tidies up after each conflict.
- **A generated index committed beside the entries.** Every entry would add a line to it, and the conflicts would
  move there.

## Costs

- Every open branch that added a section to `DESIGN.md` conflicts once with the split, and is mended by merging
  `main` and running that script to move the section, which the conflict message cannot say.
- The paper and older documents name `docs/DESIGN.md` at commits before the split, and are left as they are, since
  those commits still hold the whole file.
- Reading the design start to end is now reading a folder in order, which the documentation pages make one list.
