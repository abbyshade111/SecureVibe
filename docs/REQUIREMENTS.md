# Every ASVS and AISVS requirement, and what checks it

Generated by `tools/coverage.py` from the checks' own citations, with `docs/COVERAGE.md`. Do not
edit by hand; run `python3 tools/coverage.py` after changing a check, and the build fails until
you do. It lists every requirement, whether or not it applies to a given app; which apply is
decided per app, from its `securevibe.toml` and its code.

## How to read this

- **Can be checked**: at least one check can mark it *checked* or *needs attention*. A check
  is almost always about part of a requirement, so a clean result is one automated check that
  was satisfied, not proof the whole requirement is met.
- **A check helps; a person decides**: a check speaks to it, but it asks for something no check can settle,
  such as a documented policy or a design decision.
- **No check**: nothing in `sv` checks it. The app's own tests can still count for it when
  a passing test names the requirement's id; otherwise it stays *not verified*.
- *found failing only*: that check can show the requirement is not met, and finding nothing does
  not show it is, so a clean run credits nothing.
- *credited only*: that check can show the requirement is met, and never marks it *needs
  attention*, since the app may meet it in a way the check cannot see; it says so instead.
- Each check says what kind it is and so what it needs to run:

| Kind | Needs |
|---|---|
| Reads the code | nothing: plain `sv check` |
| Known vulnerabilities | a local copy of the OSV database (`--advisories DIR`) |
| The running app | a container backend and a `run` section (`--run`); for the AI checks, an `ai` section too |
| Signed in | the above, and a `users` section with test accounts, or an `oidc` section for a sign-in through another service |
| Outside tools | the tool installed (`--tools`) |
| Your own live site | the address your app is served from, typed at the terminal (`sv probe https://…`) |
