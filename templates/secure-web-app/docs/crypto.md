# How this app uses cryptography

Every place this app encrypts, hashes or signs something, listed from crypto-inventory.json so this document can never drift from what the code does.

## Principles

- Only algorithms built into Node.js (node:crypto) are used; there are no third-party cryptography packages.
- Keys and secrets come from the environment (.env) and are never written into code or logs.
- Random values come from the operating system's cryptographically secure generator (crypto.randomBytes / randomUUID).
- MD5 and SHA-1 are never used for security purposes (HMAC-SHA1 appears only inside the TOTP standard, RFC 6238).

| Storing user passwords | argon2id (memory 64 MiB, 3 passes, parallelism 4) when Node.js provides crypto.argon2; otherwise scrypt (N=2^17, r=8, p=1, 64-byte key) | 16 random bytes of salt per password | src/security/password.ts | Not needed; a change of algorithm is applied on the next successful sign-in when the stored format differs |

| Protecting sensitive columns at rest (one-time code seeds and fields marked sensitive) | AES-256-GCM with a 96-bit random nonce and a 128-bit authentication tag; table, column and row id are bound as additional authenticated data | FIELD_KEYS (numbered 32-byte keys); ACTIVE_FIELD_KEY chooses the key for new data | src/db/field-crypto.ts | Add a new key id, point ACTIVE_FIELD_KEY at it and run npm run rotate-field-key |
| Password reset links and invitation links | 16 random bytes (base64url) sent to the user; HMAC-SHA256 with TOKEN_HMAC_KEY stored | TOKEN_HMAC_KEY (at least 32 bytes) | src/security/password.ts, src/features/auth/index.ts | Changing TOKEN_HMAC_KEY invalidates outstanding links |
| Machine access to the JSON API (optional feature) | 32 random bytes (base64url) with an 8-character prefix; HMAC-SHA256 with TOKEN_HMAC_KEY stored | TOKEN_HMAC_KEY | src/features/apikeys/ | Keys are revoked and re-issued through the app |
| One-time codes for sign-in (RFC 6238) | HMAC-SHA1 over a 30-second counter, 6 digits, one step of tolerance, replay of an accepted step refused | 20 random bytes per user, stored with field encryption | src/security/totp.ts, src/features/auth/mfa.ts | Users can switch codes off and set them up again |
| Backup sign-in when the phone is lost | 10 codes of 10 base32 characters (50 bits each) from random bytes; HMAC-SHA256 with TOKEN_HMAC_KEY stored | TOKEN_HMAC_KEY | src/security/totp.ts, src/features/auth/mfa.ts | A new set is issued when one-time codes are set up again |
| Proving that a form or API call came from this site | 32 random bytes (base64url) kept in the server-side session and compared in constant time | none | src/security/csrf.ts | Per session |
| Allowing only the app's own scripts and styles to run | 16 random bytes (base64) per response | none | src/security/headers.ts | Per response |
| Making the security event log tamper-evident | SHA-256 over the previous row's hash plus the canonical JSON of the row | none (integrity, not secrecy) | src/security/audit.ts | Not applicable |
| Referring to sessions and email addresses in logs without revealing them | First 8 or 12 hex characters of SHA-256 | none | src/lib/logger.ts, src/security/password.ts | Not applicable |
| Encrypting traffic when TLS_MODE=selfsigned | TLS 1.2 or newer with AES-GCM and ChaCha20-Poly1305 cipher suites only | certs/key.pem and certs/cert.pem from npm run gen-cert (or a certificate you supply) | src/server.ts, scripts/gen-cert.ts | Re-run gen-cert or replace the files; restart the app |
