# Where this app can run

By default this app only answers on this computer.

## The three modes

| Mode | How to turn it on | What it means |
| --- | --- | --- |
| Just this computer (default) | Nothing to do — `BIND_LAN=0`, `TLS_MODE=off` | Only someone sitting at this computer can reach the app. No certificate is needed. |
| Other devices on your network | `BIND_LAN=1` in `.env`, and normally `TLS_MODE=selfsigned` (`npm run gen-cert` first) | Phones and laptops on the same Wi-Fi or office network can reach the app. Browsers will warn about the self-signed certificate — that is expected on a private network. |
| The internet | Put a real reverse proxy (with a certificate from a service like Let’s Encrypt) in front of the app and set `TLS_MODE=proxy` with `TRUST_PROXY_HOPS=1` (or however many proxies sit in front of it) | Anyone can reach the app. Do this only once you are ready — see the checklist below. |

## Before you go on the internet

- Put a real TLS certificate in front of the app (a reverse proxy such as Caddy, nginx or a managed load balancer is the simplest way).
- Re-check `docs/data-protection.md` and `docs/data-retention.md` — sensitive data over the internet usually needs field encryption on and a retention period set.
- Consider a secret manager instead of the `.env` file for production secrets.
- Review `docs/SECURITY.md` and make sure the contact address is real.
- Take a fresh look at rate limits: the defaults assume a small number of trusted users.

This guidance is generated from the SbD (Secure by Design) checklist controls AC-01 and DM-02, which are honestly reported as *not applicable yet* for a loopback-only app and re-evaluated once you set `TLS_MODE`.
