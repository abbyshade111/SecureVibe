## Automated-abuse protection

Every sensitive action is rate limited, and repeated sign-in failures on one account trigger a temporary slow-down (never a permanent lock):

| Limit | Applies to | Allowed | Per | Grows after repeated failures |
| --- | --- | --- | --- | --- |
| `general` | All requests | 100000 per address | 1 minute(s) | No |
| `login` | Sign-in attempts | 20 per address, 5 per account | 15 minute(s) | Yes, doubling, capped, never permanent |
| `mfa` | One-time code attempts | 5 per account | 15 minute(s) | Yes, doubling, capped, never permanent |
| `registration` | New account sign-ups | 3 per address | 60 minute(s) | No |
| `reset` | Password reset requests | 10 per address, 3 per account | 60 minute(s) | No |
| `ai` | AI assistant requests | 20 per signed-in user | 60 minute(s) | No |
| `uploads` | File uploads | 20 per signed-in user | 60 minute(s) | No |
| `api-key` | API requests per key | 120 per signed-in user | 1 minute(s) | No |

## Two-factor authentication

Administrators must set up a one-time code app before using the app. Every user may turn on one-time codes for their own account.

## Incident response

If you believe the security event log or an account was tampered with, follow docs/incident-response.md and run `npm run audit:verify` to check the tamper-evident log.
