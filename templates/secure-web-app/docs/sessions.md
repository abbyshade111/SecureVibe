# How sign-in works

A signed-in visit is called a session. Sessions are tracked on the server; the browser only holds a random, unguessable id.

| Setting | Value |
| --- | --- |
| Cookie name | `sid` |
| Cookie flags | HttpOnly, SameSite=Strict, Path=/ |
| Session id | 256 random bits (32 bytes), generated by the operating system |
| Stored as | A keyed hash of the id (HMAC-SHA256 with SESSION_SECRET) — a copy of the database alone cannot be used to sign in |
| Ends after no activity | 15 minutes |
| Ends no matter what, after | 8 hours |
| Devices signed in at once | 5 (the oldest is signed out automatically when a new one starts) |
| Re-issued on sign-in | Yes — the id used before signing in stops working the moment sign-in succeeds |
| Re-issued after a one-time code | Yes, again, for the same reason |
| Re-confirmation window for sensitive changes | 5 minutes (email address, one-time code settings) |

Signing out (or an administrator ending a session) marks it ended on the server immediately; the id in the browser stops working even if the cookie is not cleared.
Visit **Your account → Sessions** to see every device currently signed in and end any of them.
