# Payments

This app never collects, transmits or stores card numbers, expiry dates or security codes. Doing that yourself
brings a long list of PCI-DSS obligations; a small local-first app should not carry that risk. Instead, payment is
handled entirely by a provider's own **hosted checkout page**: the app sends the person to a link the provider
gives you, the provider collects payment on its own domain, and the app only ever finds out afterwards, through
the provider's dashboard or a webhook you set up separately.

## What is in this template

- `src/features/payments/index.ts` — a `/checkout` page (signed-in users only) that explains this and links to
  `CHECKOUT_LINKS.default` when one is configured.
- `src/views/payments/checkout.ejs` — its plain-language explanation.
- No dependency on any payment provider's SDK is included, and none is required for a hosted checkout link.

## Setting up a real checkout link

### Stripe

1. In the Stripe Dashboard, go to **Payment links** → **New**.
2. Add the product or price, any options you want (quantity, promotion codes), and save.
3. Stripe gives you a URL such as `https://buy.stripe.com/xxxxxxxx`. This URL is not a secret — it is safe to put
   in this app's source code.
4. Open `src/features/payments/index.ts` and set `CHECKOUT_LINKS.default` to that URL (or add more entries keyed
   by plan/product id if you offer more than one).
5. To find out when someone has paid, configure a webhook endpoint in the Stripe Dashboard. Handling that webhook
   is outside this template's scope; if you add it, send the request through the normal route registry
   (`defineRoute`) with `auth: 'public'` and verify Stripe's signature header before trusting the body — never
   trust an unsigned webhook.

### Square

1. In the Square Dashboard, go to **Payment links** and create one for your item.
2. Square gives you a URL such as `https://square.link/u/xxxxxxxx`. Like Stripe's, this is safe to keep in source
   control.
3. Set `CHECKOUT_LINKS.default` in `src/features/payments/index.ts` to that URL.
4. As with Stripe, a webhook (Square calls them "Webhook subscriptions") is the way to learn that a payment
   completed; verify its signature the same way before trusting it.

## What never belongs in this app

- Card numbers, expiry dates, CVV/CVC codes, or full magnetic-stripe/track data — even "just to pass them along".
- A payment provider's **secret** API key in a page the browser can read, in a prompt sent to an AI model, or in
  a log line. Secret keys (as opposed to the public Payment Link URL above) belong only in `.env`, are read only
  from `process.env` on the server, and are only ever needed if you build server-to-server API calls beyond the
  hosted checkout link described here.
- Any endpoint that accepts a payment amount or "paid" status directly from the browser without checking it
  against the provider. A page can *display* what it thinks happened; only a verified webhook or a server-side
  call to the provider's API should ever mark something as paid.
